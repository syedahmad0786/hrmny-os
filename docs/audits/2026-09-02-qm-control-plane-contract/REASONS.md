# Reasons

## Why this slice was selected

The earlier Sales Growth implementation was already complete and had later green phases. The remaining interrupted PostgreSQL socket-hardening worktree contains uncommitted user-owned changes and was the cyber-sensitive path. It was therefore left untouched.

The QM control-plane contract was the next bounded item that could be completed entirely with synthetic local data, without provider credentials, network actions, backend termination, connection-loss injection, billing, deployment, or a production write.

## Why the boundary is narrow

QM's reviewed security model treats the project as early and internal rather than a hardened public multi-tenant authorization layer. HRMNY therefore has to own principal verification, personal scope, capability grants, approvals, and immutable effect receipts. The contract expresses those responsibilities before any provider runtime is connected.

## Why evidence states stay separate

A green local suite proves deterministic code behavior. It does not prove a durable database transaction, a provider resource, a destination route, credential handling, rollback, recovery time, a user's workflow, or production operation. Each remains a separate acceptance state.
