# Sales & Growth workflow

Research → company review → contact search → saved lead → company brief → reviewed outreach → private conversation → next action.

- **Research:** dated public web discovery covers hiring, company news, leadership and open tenders. News/intent/tender sources must be within 30 days, hiring within 14, leadership within 90. Web results require matching provider citations; dates/excerpts remain subject to human source review. Company homepages alone do not qualify. Existing relationships, active opportunities and research within 30 days are excluded. Rework feedback informs subsequent searches.
- **Source feeds:** Research accepts a normalized JSON array from permitted datasets (including reviewed Apify exports), licensed intent exports or tender sources. Required row fields: `name`, `website`, `sector`, `kind`, `publishedOn`, `evidence`, `excerpt`, `whyNow`, `service`; tenders also require `deadline`. Dates use YYYY-MM-DD. Source ingestion never starts an Actor or purchases data. Actor-specific API automation requires a selected, authorized source and credentials; there is no blanket permission to scrape LinkedIn.
- **Research history:** one request ID identifies a run. A duplicate completed request returns the recorded result. An ambiguous or failed run is not automatically retried against a paid provider. Operator-created and scheduled research use the same proposal path. The existing AI autonomy policy controls scheduling.
- **Company intelligence:** current CRM context and the authorized legacy archive are searchable from Sales. Private meeting preparation uses the employee's Google token, bounded Drive/Gmail/Calendar results and a separate public web pass. Private correspondence is never placed in a public web-search query. Coverage identifies unavailable sources. Private briefs live in employee-owned receipts; the shared AI ledger retains usage metrics only.
- **Archive continuity:** JSON/SQLite import includes roles, relationships, communications, proposals and the Asana snapshot. Historic opportunities become restricted activities, not new forecast deals. No historic message is sent and no old automation is activated. Shared company/contact identities and roles are retained; legacy notes and communications require an explicit reader list. Apply runs in a serialized database transaction with lineage. The Settings preview reports held private rows. Existing mailbox ownership remains independent of archive access.
- **LinkedIn:** only validated HTTPS public `/in/` profile links are opened. The user copies a reviewed draft and sends it in LinkedIn, then records the outcome. No message text in URLs, cookies, account sharing, automated invitations or automated DMs. Send/acceptance receipts are employee-bound; recorded outcomes are self-reported, not provider delivery confirmations.
- **Commercial:** historical proposal values are context. Current quote rates remain awaiting owner review; no archived rate was silently promoted into the current rate card.

New discovery and meeting research require a working web/LLM provider. Gmail/Drive/Calendar require each employee's connection. Direct Asana/Canva live access and any paid intent feed need provider authorization; importing their historical references does not verify those live connections. The old Tejari stub now directs operators to real research/source intake instead of returning a fake tender.

## Validation

`pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`; the PostgreSQL CI suite includes archive transaction, replay, two-reader access and forecast isolation. Browser acceptance includes the new Company intelligence route. Provider sends remain separately approved actions.
